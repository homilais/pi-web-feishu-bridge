# 使用手册

面向**日常使用者**（飞书里怎么指挥）。环境搭建与部署见 [`IMPLEMENTATION.md`](./IMPLEMENTATION.md)。

## 1. 指令一览

| 指令 | 说明 | 回复形式 |
|---|---|---|
| `/help` | 指令帮助 | 卡片 |
| `/info` | 当前项目 + 模型，**下拉切换**项目/模型 | 卡片 |
| `/switch <项目>` | 切换项目（支持 cwd / 名称 / 路径片段） | 卡片 |
| `/model <provider>/<modelId>` | 切换模型（下一轮生效） | 文本回执 |
| `/last` | 空闲=最后一条回复；**执行中=实时进展（自动持续更新到结束）** | 卡片 |
| `/agents` | 会话列表（点击切换） | 卡片 |
| `/abort` | 停止当前任务（保留项目绑定） | 文本回执 |
| `/release` | 纯解绑，**不打断正在跑的任务** | 卡片 |
| `直接发消息` | 下发任务 | 流式卡片 |
| `回复任意卡片` | 定向到那张卡片的项目/进程 | 流式卡片 |

约定：
- **无参 `/switch`、`/model` 与未知指令**统一回 help 卡。
- 「去 /info」这类引导不再单独发文本，提示并入卡片顶部。
- 群聊内需 **@机器人**；单聊直接发。

## 2. 启动 / 停止 / 状态检查

### 启动

```bash
# 前台（Ctrl+C 停止）
npm start

# 后台（推荐：日志写到 /tmp/bridge.log）
nohup npm start > /tmp/bridge.log 2>&1 &
echo $!          # 记下 pid
tail -f /tmp/bridge.log
```

### 停止

```bash
kill 35455               # 优雅退出：拒绝 pending 审批 → 断开飞书长连接
pkill -f "src/index\.ts" # 按进程名找
```

> 桥接支持 `SIGINT`/`SIGTERM` 优雅退出。飞书同一应用**只能有一个客户端**，
> 否则事件会随机只投给其中一个 —— 启动前先确认没有旧实例。

### 检查是否连上

```bash
npm run probe:health
```

输出示例：

```
[http://127.0.0.1:30141]
  ✅ Pi-Web 已启动，鉴权通过，运行中 agent 1 个
  ✅ 会话文件 17 个，覆盖 5 个项目空间
  ✅ 模型 N 个
[飞书]
  ✅ 应用凭据有效，可换取 token（cli_xxxx…）
[本地进程]
  ✅ 桥接正在运行（pid 35455）
✅ 全部通过
```

**看启动日志判断是否就绪**：

| 日志 | 含义 |
|---|---|
| `Pi-Web 连接正常，运行中 agent N 个` | Pi-Web 通、密码对 |
| `无法连接 Pi-Web，请确认已启动且 PIWEB_PASSWORD 正确` | ❌ 进程直接退出 |
| `连接飞书长连接…` → `✅ 桥接已就绪` | ✅ 全部就绪 |
| `[lark] 飞书长连接重连中…` / `已重连` | 网络抖动，自动恢复 |
| `[lark] 消息被策略拒绝` | 白名单拦截（open_id / groupAllowlist） |
| `[lark] 11205 …` | 机器人能力未启用，或权限未发布版本 |
| `收到 SIGTERM，关闭中…` | 正常退出 |

**在飞书里验证**：发 `/help`，收到帮助卡即端到端打通。

> `probe:health` 不启动桥接，只检查两端连通性；即使桥接没在跑也能单独诊断。

## 3. 卡片一览

所有卡片都是 **V2 schema**，统一样式：**主标题=项目名，副标题=状态/耗时，正文=内容+操作**。

| 卡片 | 主标题 | 副标题 | 正文 | 配色 |
|---|---|---|---|---|
| **任务卡（运行中）** | 项目名 | `⏱ 已用时` | 进度（默认展开）+「⏹ 停止」按钮 | 蓝 |
| **任务卡（完成）** | 项目名 | `🔧 N 次 · ⏱ Xs` | `📝 结果` + 折叠过程 | 绿 |
| **任务卡（出错）** | 项目名 | `❌ 出错：…` | 错误详情 | 红 |
| **任务卡（待审批）** | 项目名 | — | 「✅ 允许」「❌ 拒绝」并排 | 橙 |
| **/info** | 项目名 | 状态 · 模型 | 切换项目下拉 + 切换模型下拉 | 蓝 |
| **/last（空闲）** | `📝 项目名` | 状态 · 模型 | 最后一条回复（markdown） | 绿 |
| **/last（执行中）** | `🔴 项目名` | `已运行 Xs · 🔧 N 次` | 当前任务 + 进展 + 正在输出 | 蓝 |
| **/agents** | `🗂 会话记录` | `N 个会话 · 当前：X` | 每行一个切换按钮 | 蓝 |
| **/help** | 指令帮助 | — | 查询 / 控制 / 技巧 三组 | 蓝 |

## 4. 常见场景

| 想做什么 | 怎么做 |
|---|---|
| 同时推进多个任务 | 给**不同项目**各发一条消息，并行执行 |
| 直接下任务 | 发消息即可，流式卡片实时回传 |
| 看正在跑什么 | 发 `/last`（执行中会持续更新进展到结束） |
| 换一个项目 | `/info` 下拉选，或回复那张项目的任务卡 |
| 换模型 | `/info` 下拉选，或 `/model <provider/modelId>` |
| 中止任务 | 点任务卡「⏹ 停止」，或 `/abort` |
| 审批工具操作 | 点审批卡「✅ 允许」/「❌ 拒绝」 |
| 释放给本地终端 | `/release`（不打断任务，下次提示重选项目） |
| 看有哪些会话 | `/agents`，点击切换 |
| 让结果推到别的项目 | 回复那个项目的任意卡片后发消息 |

## 5. 机制说明

**并发粒度** —— 这是本项目的核心能力：**不同项目的 agent 并行执行**，**同一项目的任务串行排队**。

| | 行为 | 原因 |
|---|---|---|
| 不同项目 | 同时跑，各自流式卡片互不干扰 | 每个项目独立 agent 进程 |
| 同一项目 | 排队依次执行 | 同一 agent 共享一份 session 文件，并发写会冲突 |

想同时推进多个任务，就把它们分派到**不同项目**；同一项目内发多条消息会在该 agent 的队列里依次执行，不会丢。

**按项目复用 agent** —— 绑定粒度是**项目（cwd）**，不是飞书会话。同一项目的多个飞书会话共享同一个 agent 进程与上下文。三级复用：① 采纳 pi-web 内存中该项目的活跃 session；② 复用已记录的 agentId；③ 新建。agent 失效（404/502）会自动清除重建一次。

**回复卡片定向** —— 桥接在服务端记录了「卡片 → 项目/进程」的映射（不显示在卡片上）。**回复任意卡片**发消息，会自动切到那张卡片对应的项目/进程，无需先 `/switch`。

**进展怎么拿到的** —— `/last` 在任务执行中时，会**挂接一条 SSE 订阅**持续接收事件，用流式卡片实时更新到任务结束；若本会话已有正在流式的那张任务卡，则不重复建卡，只提示去那张卡看。

**卡片更新频率** —— 任务卡每 ~450ms 检查一次，内容有变化才推送。任务空闲时的 `/last` 返回最后一条回复（静态快照）。

**结果推送到哪** —— 任务卡推送到**发起任务的会话**。从别的会话用 `/last` 观察，能看到进展，但结果不会推到那个会话。

## 6. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 发消息没反应 | ① 群里未 @机器人；② 桥接未启动；③ 飞书后台未订阅 `im.message.receive_v1` 或权限未发布版本 |
| 卡片按钮点了没反应 | 后台未订阅 `card.action.trigger`；或权限未发布版本 |
| 显示「不在操作白名单内」 | 你的 open_id 不在 `LARK_ALLOW_OPEN_IDS` 里（单聊白名单） |
| 提示「没找到「X」」 | 项目名不匹配，发 `/info` 从下拉选，或看 `/agents` |
| 「⚪ 已回收」 | agent 进程不在内存了。点击会自动解绑，发条消息会重新创建 |
| 任务卡卡住不动 | 模型在思考或工具执行中；发 `/last` 看具体进展，`/abort` 可中止 |
| 桥接重启后收不到消息 | 飞书同应用只能有一个客户端；确认没有其他实例在跑 |

排错时看日志：`/tmp/bridge-v2.log`（或启动时重定向的输出）。

## 7. 已知限制

- `PI_WEB_IDLE_TIMEOUT_MS` 建议设 `0`（桥接常驻）；设小值会让 agent 被回收，表现为「⚪ 已回收」。
- 会话释放无显式接口，靠 idle 超时；`/release` 只做**桥接侧解绑**，不主动 kill agent。
- 进展卡是快照，不是实时流；要看持续更新请看任务卡本身。
- 模型需选稳定的：部分供应商/模型会间歇返回空文本（触发 auto_retry）；换模型之前先用小任务验证。
